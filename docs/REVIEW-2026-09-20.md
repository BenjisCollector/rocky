# Rocky review, 2026-09-20

Static review of commit `c5076bd` against the promises in `README.md` and `docs/ROADMAP.md`. Method: read every module under `rocky/` and `rocky/platform/`, traced each input that reaches `Platform`, ran `uv run pytest -q` offline (203 passed, 1 skipped), and reproduced each finding below with the `Fake` platform or a one-line Python check. Nothing was run live: no microphone, no voice loop, no synthetic input. No files other than this one were changed.

Severity: Critical means the promise breaks in the default configuration with no user action beyond a normal command. High means the promise breaks under `--act` or the panel's "Do it", or on a common screen. Medium means the promise is weakened or the guard is latent. Low is hygiene.

Summary: 0 Critical, 4 High, 3 Medium, 9 Low. Promises 1 (choice validation), 5 (secrets) and 6 (main-thread safety) hold. Promises 2, 3, 4 and 7 have gaps.

## High

### H1. Writer output can carry newline and tab, which `type_text` turns into Return and Tab keystrokes

**Where.** `rocky/writer.py:83-92` (`parse`), `rocky/platform/macos.py:379-384`, `rocky/platform/windows.py:220-224`.

**Evidence.** `parse` accepts any JSON string of 1..200 characters. Reproduced: `writer.parse('{"text": "Thanks,\\nYousef"}')` returns `'Thanks,\nYousef'` and `writer.parse('{"text": "a@b.com\\thunter2"}')` returns `'a@b.com\thunter2'`. Both platforms' `type_text` map `\n` to a Return press and `\t` to a Tab press. The writer's system prompt (`writer.py:26-31`) says nothing about line breaks.

**Failure scenario.** Goal "reply to the last message saying thanks" in Teams, Slack or Messages with "Do it" on. The loop picks `type_text` into the body. No span fits, so the small model answers `{"text": "Thanks,\nYousef"}`. Rocky types "Thanks,", presses Return, and the message is sent. The send never went through `risk.py`; `send` is in the destructive list for shortcuts and labels but a Return generated from model text is neither. A tab is worse: `"email@x.com\thunter2"` types the address, moves focus to the next field, and types the rest there. If the next field is a password field, promise 2 breaks as well.

**Smallest fix.** One guard in `parse`, which is the single trust boundary for model text:

```python
text = data["text"].strip()
if any(ord(c) < 32 for c in text):
    return ""
```

Add one parametrized case to `tests/test_writer.py::test_parse_refuses_anything_but_a_small_text_object` with `'{"text": "a\\nb"}'` and `'{"text": "a\\tb"}'`.

### H2. Neither the goal loop nor the fast path checks that the frontmost app is still the intended target before sending input

**Where.** `rocky/loop.py:99-107` and `rocky/loop.py:123-137` (`execute`), `rocky/fast.py:47-54` and `rocky/fast.py:68-77` (`_type`, shortcut press). `Platform.focus_app` exists (`rocky/platform/base.py:19`) and has no callers outside `tests/test_macos_ax.py:52`.

**Evidence.** The goal loop perceives at `loop.py:68`, spends the Jev round trip (measured 457 ms median) at `loop.py:71`, takes a full-screen `screencapture` at `loop.py:99`, then clicks the coordinates of the old snapshot at `loop.py:127` or clicks and types at `loop.py:134-136`. `snapshot.app` is known at `loop.py:68` and never compared with `platform.frontmost_app()` again. On the fast path, `route()` records `frontmost_app` into the Jev state at `router.py:245` and the `Plan` drops it; `_type` and the shortcut branch send to whatever is frontmost at execution time.

**Failure scenario.** This is the class of incident that put keystrokes into a Teams window. The user says "watermelon, type see you at three" while looking at Notes. During the router round trip, a Teams call window or a notification steals focus. `_type` reads a snapshot of Teams, finds no focused secret field, and types into the Teams compose box. A shortcut plan for `send` (cmd+Return, confirmed by the user against Mail) lands in Teams the same way. In the goal loop, a `press_enter` step decided against a Finder sheet is pressed in whatever app came to the front during the screenshot.

**Smallest fix.** Two guards that reuse what already exists.

Goal loop, in `run_goal` before the `else:` branch at `loop.py:103`:

```python
front = platform.frontmost_app()
if front != snapshot.app:
    result.note = f"refused: focus moved to {front!r}"
elif decision.kind == "type_text" and is_secret_field(decision.item.label):
```

And in `loop.execute` for `type_text`, after the click at `loop.py:135`, reuse `find_field` to check the field took focus before typing:

```python
target = find_field(platform, item)
if not (target and target.focused):
    return "refused: field did not take focus"
```

Fast path: add `front: str = ""` to `Plan` (`models.py:47-57`), set `front=platform.frontmost_app()` in `route()` where it is already read (`router.py:245`, pass it through `to_plan`), and in `fast.execute` before the `type`, `shortcut` and `scroll` branches:

```python
if kind in ("type", "shortcut", "scroll") and plan.front and platform.frontmost_app() != plan.front:
    return f"Focus moved to {platform.frontmost_app()}. Nothing sent."
```

`open_app`, `open_url`, `search`, `volume`, `media` and `system` are exempt because changing the front app is their job or they are global.

### H3. Fast-path `type` types into a focused password field because the walker hides that field from the check

**Where.** `rocky/fast.py:72-76`, `rocky/platform/macos.py:176-192` (`KEEP_ROLES`, comment "AXSecureTextField is deliberately absent"), `rocky/platform/windows.py:414-415` (`IsPassword` skipped).

**Evidence.** `_type` looks for the focused item in `platform.snapshot().items` and refuses only if that item's label is secret. Both walkers drop secure fields before they reach `items`, so when the focused control is a password field the generator at `fast.py:73` yields `None`, the check at `fast.py:74` passes, and `fast.py:76` types. Reproduced with `Fake(items=[Item(1, "AXButton", "Sign in", ...)])`, which is exactly what the macOS walker produces for a login form whose password box has focus: `execute(Plan(kind="type", args={"text": "hunter2"}, confidence=0.9), fake)` returns `"Done."` and records `("type_text", "hunter2")`. The existing test `tests/test_fast.py:70-78` passes an `AXSecureTextField` item with `focused=True` into `Fake`, a fixture the real walker can never emit, so the suite gives false assurance here.

**Failure scenario.** The user is on a login page with the cursor in the password box (after typing a username and pressing Tab, or after a site autofocuses it). "watermelon, type hello" puts "hello" into the password field. README line 102 says this cannot happen. The text guard at `fast.py:70` catches "type my password hunter2" and misses "type hunter2".

**Smallest fix.** Ask the OS for the focused element's role directly; the item list excludes the role in question, so it can never answer this. Add one method to the contract:

`rocky/platform/base.py`: `def focused_role(self) -> str: ...`

`rocky/platform/macos.py`:

```python
def focused_role(self) -> str:
    app = AS.AXUIElementCreateApplication(self._frontmost_pid())
    return _ax_str(_ax(app, "AXFocusedUIElement"), "AXRole")
```

`rocky/platform/windows.py`: return `"password"` when `auto.GetFocusedControl().IsPassword` else the `ControlTypeName`. `rocky/platform/fake.py`: return `self.focused_role` (default `""`).

Then in `fast._type`, before the snapshot at `fast.py:73`:

```python
if platform.focused_role() in ("AXSecureTextField", "password"):
    return "I never type into password or card fields."
```

Rewrite `tests/test_fast.py:70-78` so the `Fake` has no secure item and `focused_role = "AXSecureTextField"`, which is the real shape. Interim one-liner if the contract change waits: refuse when `focused is None` at `fast.py:74`, which fails closed at the cost of fields the AX tree does not mark focused.

### H4. The destructive gate in the goal loop misses `press_enter` and common button labels

**Where.** `rocky/risk.py:13-17` (`_DESTRUCTIVE_WORDS`), `rocky/risk.py:44-50` (`classify` for `Decision`), `rocky/loop.py:94-97`.

**Evidence.** `classify(Decision)` inspects only `click_item` labels and `type_text` secret labels. `classify(Decision(kind="press_enter"))` returns `"reversible"`. The decision kind text at `decide.py:25` tells Jev that `press_enter` will "confirm the default button". Reproduced label checks: `Move to Bin`, `Confirm`, `Clear`, `OK`, `Yes`, `Publish`, `Post`, `Sign out`, `Archive` all classify as reversible; `Empty Bin` and `Delete` classify as destructive. Goal sentences "clean up my desktop" and "get rid of the old photos" classify as reversible at plan level, so no yes is asked before the loop starts.

**Failure scenario.** "Do it" is on. "watermelon, clean up my desktop." No plan-level confirmation (no listed word). Step 1 clicks a file. Step 2 clicks "Move to Bin" (UK English macOS labels the Trash "Bin"; the list has `trash` and not `bin`). Or the app raises a sheet "Delete 3 items?" with a default "Delete" button and Jev picks `press_enter`, which the kind description invites. Return is pressed at `loop.py:139` with no gate. The same path covers a payment sheet whose default button is "Pay", a chat compose box where Return sends, and "Confirm" on a checkout page.

**Smallest fix.** Two small changes in `risk.py` and one in `loop.py`.

1. Extend the word list at `risk.py:14-15` with `bin|clear|confirm|publish|post|tweet|share|archive|sign out|log out|block|report|leave`. `ok` and `yes` are left out because they would gate every dialog; item 3 below covers them.
2. In `classify(Decision)` add `if action.kind == "press_enter": return "destructive"` only when the caller passes the visible items, which needs a parameter. Cheaper: do it in the loop.
3. In `run_goal` at `loop.py:94`, treat Return as destructive when any visible button carries a destructive label or the window title does:

```python
sheet = decision.kind == "press_enter" and any(
    requires_confirmation(it.label) for it in items if "button" in it.role.lower()
)
if (requires_confirmation(decision) or sheet) and not (confirm and confirm(what)):
```

Add a test in `tests/test_loop.py` with a `button(1, "Delete")` on screen and a `press_enter` decision, asserting `outcome == "needs confirmation"` and no `press` call.

## Medium

### M1. The goal loop never applies `DESTRUCTIVE_MIN_CONFIDENCE`, and no production caller wires `confirm`, so a confirmed destructive goal can never finish

**Where.** `rocky/loop.py:86-97`, `rocky/fast.py:87`, `rocky/risk.py:67-83`.

**Evidence.** `run_goal` compares `decision.confidence` with `GOAL_MIN_CONFIDENCE` (0.5) at `loop.py:86` and never with `DESTRUCTIVE_MIN_CONFIDENCE` (0.8). `risk.check` is not called for a `Decision`; `requires_confirmation` at `loop.py:94` is a boolean only. `fast._goal` calls `run_goal(platform, jev, plan.args["goal"], act, print)` with no `confirm=` and no `utterance=`; `tests/test_fast.py:88-90` pins that five-argument shape. README line 101 promises the higher floor for every destructive action.

**Failure scenario.** Today the gap is latent: with `confirm=None` every destructive step ends the run at `loop.py:96` with `needs confirmation`, so "delete this draft" can be confirmed at plan level (`fast.py:29`) and then never completes, which is the functional half of the bug. The safety half appears the moment anyone passes `confirm=` (the app shell's `self.confirm` is the obvious candidate and Phase 1 item 3 of the roadmap heads there): a `click_item [4] Delete` at confidence 0.55 would then execute after a spoken yes, below the floor the README promises.

**Smallest fix.** Route the decision through `risk.check`, which already knows the floor and the yes gate. In `run_goal` replace `loop.py:94-97` with:

```python
refusal = risk.check(decision, decision.confidence, prompt_fn) if prompt_fn else (
    "needs confirmation" if requires_confirmation(decision) else ""
)
if refusal:
    log(refusal); state.outcome = "needs confirmation"; return state
```

with `prompt_fn: Callable[[str], str] | None = None` replacing the `confirm` parameter, and `fast._goal` passing the same `prompt_fn` it received. That gives the CLI its terminal prompt and the app shell its five-second listen for goal steps too, with one code path for both. Update `tests/test_loop.py:131-142` and `tests/test_fast.py:87-103` for the new keyword.

### M2. Values of secret-labelled text fields are sent to TypeSafe

**Where.** `rocky/decide.py:71-88` (`build_state`, `"value": it.value[:200]`), `rocky/decide.py:60-64` (`describe`, value in the criteria), `rocky/platform/macos.py:584` (`value=_ax_str(node, "AXValue")` for `TEXT_ROLES`), `rocky/platform/windows.py:424-427`.

**Evidence.** Secure fields are excluded by role (H3), but a web payment form renders the card number, expiry and often the CVC as ordinary `AXTextField`s with labels like "Card number" and "Security code". `is_secret_field` (`risk.py:27-29`) recognises those labels and returns True for `"Card number"`. Nothing consults it before the value is placed into `state.items[].value` and the `click_target` criteria, both of which travel to `api.typesafe.ai` on every goal step. The README's "No screenshots go to a model" holds; the typed digits go as text.

**Failure scenario.** The user has a checkout page open with the card number entered and says "watermelon, apply the coupon code SAVE10". Every step of the loop sends the 16 digits to the classifier API under the user's key. `run.json` does not store the state, so the run folder is clean; the network request is the exposure.

**Smallest fix.** Blank the value at the one place items are prepared for the model, `perceive.perceive` at `perceive.py:46`:

```python
items.append(replace(it, index=len(items) + 1, value="" if is_secret_field(it.label) else it.value))
```

with `from .risk import is_secret_field` at the top. `verify_typed` at `decide.py:148-167` never runs for a secret field because `loop.py:101` refuses first, so it needs no change. One test in `tests/test_perceive.py`: a `textfield(1, "Card number", value="4111...")` comes back with `value == ""`.

### M3. The goal loop never receives the utterance, so the span-first rule in the writer is dead in production and the small model is always asked

**Where.** `rocky/fast.py:87`, `rocky/loop.py:131` (`compose(goal, item.label, utterance)` with `utterance=None`), `rocky/writer.py:45-52`.

**Evidence.** `fast._goal` passes no `utterance`. `compose` then calls `select_span(field_label, "")`, which returns `""` (reproduced), and falls through to `_ask_llm`. Every live `runs/*/run.json` in the checkout records `"utterance": null`. README line 19 and ROADMAP line 142 promise a span from the user's own words first and the model second. The router already stores the utterance as `plan.args["goal"]` (`router.py:294`), so the value is at hand.

**Failure scenario.** "watermelon, search youtube for lofi beats in the app" reaches a `type_text` step. The span cutter would offer `lofi beats`. Instead DeepSeek is asked, latency and cost rise, and the typed text is whatever the model invents from the goal, which is the case the span rule exists to avoid. Combined with H1 the model gets a turn it should never have had.

**Smallest fix.** `fast.py:87`: `run_goal(platform, jev, plan.args["goal"], act, print, utterance=plan.args["goal"])`. Update the pinned call shape in `tests/test_fast.py:88-90`. When the writer key is unset the loop currently types nothing on these steps; after the fix it types the span, which is the documented behaviour.

## Low

### L1. The app shell keeps the capture thread recording during the confirmation window, so the spoken "yes" is also queued as a command

`rocky/voice.py:519-535` (capture thread keeps feeding `utterances`) and `rocky/voice.py:573-599` (`listen_once` opens a second `Microphone`). After the destructive action completes, `listen_forever` at `voice.py:557-563` transcribes the queued "yes" and hands it to the router with `addressed` left to Jev. `listen_once` also emits `idle` in its `finally` at `voice.py:598` while the destructive action is still executing, so the overlay drops out of `thinking` mid-action. Fix: set a `threading.Event` that `capture` checks before `endpointer.feed`, and have `listen_once` accept the existing endpointer and mic so it opens no second stream; or after `confirm` returns, drain the queue once.

### L2. CLI voice mode dies on a malformed router answer that is not a `JevError`

`rocky/cli.py:33-37` catches only `JevError` around `route`. A missing head (`answers["needs_screen"]` at `router.py:292`, `answers["addressed"]` at `router.py:300`) raises `KeyError`, and a non-numeric `noul` raises `ValueError` in `noul()` (`jev.py:81-86`). Neither is caught; the exception leaves `listen_forever`, the worker thread ends, and `run_with_overlay` terminates the app (`overlay.py:303-309`). Nothing executes, so this is availability only. The app shell catches everything at `app.py:458`. Fix: `except (JevError, KeyError, ValueError, TypeError)` at `cli.py:35`, or validate the three noul answers the way `pick` validates choices.

### L3. API keys are placed in `os.environ` and inherited by every child process

`rocky/config.py:33-42` writes `.env` into the process environment; `subprocess.Popen(cmd)` at `voice.py:287` starts a long-lived `whisper-server` with `TYPESAFE_API_KEY` and `TEXT_MODEL_API_KEY` in its environment, and `osascript`, `open`, `screencapture`, `pmset` and `powershell` inherit the same. Same user, same machine, so exposure is limited to processes that already run as the user. Fix: pass `env={k: v for k, v in os.environ.items() if not k.endswith("_API_KEY")}` to the `Popen` at `voice.py:287`, or have `load_env_file` return a dict that `config` reads without touching `os.environ`.

### L4. AppleScript and PowerShell strings are built by interpolation

`rocky/platform/macos.py:359` interpolates an app name into `tell application "{name}" to activate`; `focus_app` has no production caller today (only `tests/test_macos_ax.py:52`), and names come from `.app` stems on disk (`macos.py:336-340`). `rocky/platform/windows.py:351` interpolates a path into a PowerShell command; the path comes from `ROCKY_RUNS_DIR` or `Path.home()`. Neither is reachable from a model answer now. Fix when either gains a caller: pass the name as an argument (`osascript -e 'on run argv' ...`) and single-quote-escape the path (`str(out).replace("'", "''")`).

### L5. `domain_guess` synthesises `.com` from arbitrary words

`rocky/router.py:138-156`: "open my notes" yields `mynotes.com` and is offered as the `url` site; Jev is told to pick `url` only when the user said an address, and `open_url` opens it at the fast-path floor of 0.45. A mishearing can open a typo-squat domain. Fix: offer `url` only when `_DOMAIN` matched or the utterance contains "dot"; drop the bare-word `.com` synthesis.

### L6. The overlay swaps two attributes from the voice thread without a lock

`rocky/overlay.py:107-110` writes `state` and `state_since` from `set_state` on whatever thread emitted; `drawRect_` on the main-thread timer (`overlay.py:257-258`) may read the new `state` with the old `state_since` for one frame. Each write is atomic under the GIL, so this is a one-frame visual glitch and no AppKit call crosses threads. Promise 6 holds; noting for completeness. Fix: store a single tuple.

### L7. Full-screen screenshots are written to `runs/` before every executed step

`rocky/loop.py:99` calls `platform.screenshot` which runs `screencapture -x` of the whole display (`macos.py:505-508`), so PNGs in `runs/` include every window on screen, including a chat or bank window behind the target app. `runs/` is gitignored (`.gitignore:2`) and no key appears in any current run file (grepped). Fix: capture only the front window (`screencapture -l <windowid>` using the id `_front_window_bounds` already enumerates at `macos.py:432-440`), or gate the PNG behind an env flag.

### L8. `checked` in `decide.py` has an unreachable branch

`rocky/decide.py:119`: `validate_choice` either raises or returns the answer, so `ok is False` never holds and the second condition repeats what `validate_choice` already proved. Harmless. Fix: delete lines 119-120.

### L9. The fast-path secret-field test uses a fixture the real walker cannot produce

`tests/test_fast.py:70-78` puts an `AXSecureTextField` with `focused=True` into `Fake`; `KEEP_ROLES` at `macos.py:177-192` guarantees the real snapshot never contains that role. The test passes and proves nothing about the production path (see H3). Fix: covered by the H3 test rewrite.

## Promises that hold, with evidence

**1. A model answer outside the offered criteria never executes.** `validate_choice` at `jev.py:62-78` requires `choice in ids`, `set(probabilities) <= ids`, and every number a finite `int` or `float` in `[0, 1]` (`bool` is excluded because the check uses `type(n)`, which `isinstance` would let through). Reproduced: a foreign choice, a `True` confidence, an extra probability key and a list-valued choice are all refused. Every router head goes through `pick` at `router.py:261-263`, so `cands[tkey]`, `SITES[site]`, `ENGINES[...]`, `platform.shortcuts()[...]` and `platform.system(op)` only ever see offered ids. Every loop head goes through `checked` at `decide.py:112-121`, and `by_index` at `decide.py:141-142` is built from the same `items` the criteria were built from, after `perceive` renumbers them 1..N (`perceive.py:46`). `build_questions` at `decide.py:91-109` omits `click_item` when there are no items and `type_text` when nothing is editable, so those kinds cannot be chosen either. The three noul answers (`addressed`, `compound`, `needs_screen`) are read without validation at `router.py:292-301`; a bad value only changes gating or raises (L2), it cannot execute anything. Compound parts are split by regex from the user's own words (`router.py:307-315`) and each part is routed and gated on its own in both `cli.py:39-45` and `app.py:474-481`.

**2. Secret fields.** The goal loop holds: `type_text` targets come only from `editable` items (`decide.py:92, 104-108`), secure roles never enter `items` (`macos.py:176-192`, `windows.py:414-415`), the label is checked before confirmation at `loop.py:94` via `classify` and again before execution at `loop.py:101`, and `writer.compose` returns `""` for a secret label at `writer.py:47-48`. `risk.check` refuses a secret `type_text` even after a yes at `risk.py:70-76` (tested at `tests/test_risk.py:94`). The fast path does not hold (H3), and H1 opens a second route through Tab.

**3. Destructive actions.** CLI: `cli.handle` at `cli.py:51` calls `fast.execute`, which calls `risk.check(plan, plan.confidence, prompt_fn)` at `fast.py:29` before any branch, with the terminal `input` as the prompt; compound parts recurse through the same `handle` at `cli.py:44`. App shell: `runUtterance` at `app.py:476, 480` passes `prompt_fn=self.confirm` for the single and the compound case, and `confirm` at `app.py:484-489` listens for five seconds; `risk.confirm` at `risk.py:58-64` accepts only `yes` or `confirm` after stripping trailing `.`/`!`, so "watermelon yes" cancels (reproduced) and a mic error propagates to `app.py:458` and executes nothing. The floor is applied at `risk.py:79-80`. System ops offered to Jev are `dark_mode`, `lock`, `sleep_display`, `screenshot` (`router.py:63-68`); `lock` and `sleep_display` are in `DESTRUCTIVE_SYSTEM_OPS` (`risk.py:11`). Shortcuts `send`, `quit`, `delete_line`, `delete_word` match `_DESTRUCTIVE_SHORTCUT` (`risk.py:12`). Goal-tier plans are classified on the goal sentence at `risk.py:41-42`. Gaps: H4 (labels and `press_enter` inside the loop) and M1 (floor inside the loop, confirm never wired).

**4. The model never produces coordinates, selectors, shell or JavaScript that execute.** Clicks use `item.center` from the AX frame (`loop.py:127`, `models.py:28-30`). Shell calls: `_osascript` at `macos.py:210-214` is called with string constants except `focus_app` (L4, unreachable from a model answer); `open -a name` at `macos.py:351` and `open url` at `macos.py:373` are argument lists with no shell; `name` is a validated `installed_apps()` entry and `url` is a `SITES`/`ENGINES` constant or `https://` plus a regex match on the user's words. `whisper-server` at `voice.py:273-287` is a constant argument list. Windows: `os.startfile`, `webbrowser.open`, `rundll32`, and the PowerShell screenshot (L4). No `eval`, `exec`, `shell=True` or `os.system` anywhere under `rocky/`. The one model-to-keystroke path is the writer's text (H1).

**5. Secrets.** `.env` is gitignored (`.gitignore:1`) and untracked; `.env.example` is tracked with empty key values. `cli.doctor` prints `set`/`missing` only (`cli.py:69`). `JevError` messages at `jev.py:31, 40, 49, 51, 53, 57` include status codes and up to 200 bytes of response body; the Authorization header appears in none of them. `writer._ask_llm` returns `""` on error without logging (`writer.py:76-80`). `run.json` (`loop.py:170-200`) stores goal, utterance, outcome, steps, history, timings, raw answers and floors; the five run folders in the checkout were grepped for `sk-`, `api_key`, `Bearer` and the two variable names with no hits. `scripts/build_app.sh:43-48` reads `.env` from `ROCKY_HOME` at launch and copies nothing into the bundle. L3 is the one hygiene note.

**6. Main-thread safety.** `events.emit` at `events.py:22-27` copies the subscriber list under the lock and calls each outside it, swallowing exceptions. `AppController.onEvent` at `app.py:503-505` hops to the main thread with `performSelectorOnMainThread_withObject_waitUntilDone_("applyState:", ...)`; every other UI write from the voice thread goes through `main()` at `app.py:493-501`, which checks `NSThread.isMainThread()` and otherwise performs `call:` on the main thread. `voiceLoop`'s error path (`app.py:447`) and `confirm`'s prompt (`app.py:488`) use the same hop. `Overlay.set_state` at `overlay.py:294-296` touches no AppKit object; the redraw runs on an `NSTimer` on the main thread (`overlay.py:283-285, 257-258`). The hold-to-talk tap owns its own thread and run loop (`voice.py:416, 455-459`) and only sets a `threading.Event` and emits. CLI mode creates the overlay on the main thread and runs the voice worker on a daemon thread that asks the main thread to terminate when it ends (`overlay.py:298-312`). L6 is cosmetic.

**7. Wrong-app input.** Does not hold; see H2.

## Suggested order
